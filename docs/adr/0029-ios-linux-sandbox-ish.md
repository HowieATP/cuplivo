# ADR-0029: iOS Linux sandbox via embedded iSH-ARM64, shared rootfs + workspace bind mounts

The Android workspace sandbox (proot + per-workspace Ubuntu rootfs + apt, ADR-era commit `37a7ef97`) needed an iOS counterpart with the same model-facing contract: a `shell` workspace tool that runs commands in a Linux guest where `/workspace` is the bound workspace's host directory.

Decision: embed the iSH-ARM64 userland emulator (OpenMinis/ish-arm64 fork of iSH, GPL-3.0 with an explicit App Store exception — compatible with Cuplivo's AGPL-3.0; see `ios/sandbox/NOTICE`) as static libraries in the iOS Runner, running an Alpine Linux aarch64 guest inside the app process. The integration follows the OpenMinis reference implementation, with all Minis-specific offloads/hooks removed; the glue code in this repo is adapted (not copied from proot launchers).

## Hard constraints that shaped the design

1. **The iSH kernel boots exactly once per app process.** `become_first_process()` irreversibly turns the calling thread into guest PID 1 against one mounted fakefs tree; there is no un-mount or re-boot. Therefore the Android model (one rootfs per workspace under `<ws>/.sandbox/linux`) is impossible on iOS. Instead there is ONE shared rootfs at `Application Support/linux-sandbox/alpine-rootfs` (Application Support, not Documents, because `UIFileSharingEnabled` exposes Documents in the Files app), and each workspace's host directory is exposed via `fakefs_bind_mount("/workspace", hostPath)` at exec time — fakefs rebinds the same guest path in place when the workspace changes. Multi-workspace switching works within one process; reinstalling the base while the kernel is booted is rejected with `booted_restart_required` (app relaunch required).
2. **fakefs format, not plain files.** iSH's root filesystem is `data/` (path-based layout) + `meta.db` (SQLite: `stats(inode pk, stat blob)` / `paths(path blob pk, inode)`, `user_version=3`, 16-byte LE stat blob `{mode,uid,gid,rdev}`; symlinks stored as regular files containing the target). The rootfs therefore ships as a pre-converted zip bundled in the app (`ios/sandbox/resources/alpine-rootfs.zip`, ~4 MB) instead of being downloaded like Android's Ubuntu tarball — on-device tar.gz→fakefs conversion would require porting fakefsify + libarchive for no user benefit. The zip is generated by `tools/ios_rootfs/prepare_alpine_fakefs.py` (pure-Python fakefsify replica: same schema, path normalization, symlink model, traversal guards) and committed.
3. **No JIT.** The asbestos engine is a threaded interpreter (no dynamic code emission), so no JIT entitlement is needed and the App Store path is the same as iSH's. Guest crashes are contained: signal handlers recover JIT-less faults on iSH threads and re-raise untouched on Flutter threads; `die()` parks the faulting thread instead of aborting the app (`CuplivoISHCrashGuards`).
4. **Alpine ⇒ apk, not apt.** Dependency installs use staged apk steps (`recover` = stale lock removal, `update`, `install`): python→`python3 py3-pip`, nodejs→`nodejs npm`, git→`git`, build-essential→`build-base`. Custom/named mirrors rewrite `/etc/apk/repositories` for the bundled Alpine version (3.21). Node runs with `NODE_OPTIONS=--jitless` (V8 cannot JIT under emulation).
5. **iSH libraries are built from source, never committed.** `ios/sandbox/build_ish.sh` clones the pinned ish-arm64 revision and cross-compiles `libish.a`/`libish_emu.a`/`libfakefs.a` with meson/ninja (macOS + Xcode + LLVM only; outputs gitignored). The CI iOS job runs it before `flutter build ios`; the VDSO is embedded into libish via `.incbin` at library build time, so no runtime resource is needed.

## Unchanged surfaces

- MethodChannel contract `cuplivo/linux_sandbox` (`isSupported`/`getAbi`/`installBase`/`exec`) mirrors the Android plugin; `exec` keeps the `{workspacePath, command, cwd?, timeoutMs}` → `{exitCode, stdout, stderr, timedOut}` shape plus an iOS-only `rootfsPath` argument.
- Model-facing vocabulary is untouched: `/workspace` guest root, cwd mapping (`null`→`/workspace`, relative→`/workspace/<rel>`), 128K-char output cap, approval flow, prompt reminders.
- The shared rootfs is sandbox-runtime state, NOT workspace content: it is excluded from backups/sync (it lives outside `@workspaces`), and `clearAllData` does not need to touch it (app data directory lifecycle).

## Considered options

1. **Shared rootfs + bind mounts (chosen).** Only design compatible with boot-once; matches OpenMinis; zero model-contract churn. Cost: all iOS workspaces share one guest package space (an apk install in one workspace is visible in all) — accepted; per-workspace isolation on iOS would need per-workspace kernels, i.e. app relaunch per switch.
2. **Per-workspace rootfs like Android.** Rejected: boot-once constraint makes workspace switching require an app relaunch; also multiplies ~13 MB fakefs per workspace.
3. **On-device download + tar.gz→fakefs conversion.** Rejected: requires shipping libarchive or a native fakefsify port for a one-time 4 MB extraction; the bundled zip installs offline in seconds.
4. **QEMU/UTM-style full VM.** Rejected: heavyweight, JIT entitlement issues, much larger dependency; iSH's userland emulation is the proven App Store approach.

## Consequences

- iOS minimum deployment target raised 13.0 → 14.0 (iSH build requirement; Podfile + Runner target updated).
- IPA grows ~4 MB (rootfs zip) plus linked iSH code.
- The iOS shell tool needs the base dependency installed once (workspace detail page, same UI as Android); reinstall while running requires app relaunch (surfaced as a clear error).
- Native iOS code cannot be compile-verified without macOS/Xcode; first real verification is the CI iOS build + device testing (see delivery notes / manual test plan).
- GPL-3.0 attribution lives in `ios/sandbox/NOTICE`; AGPL↔GPL compatibility is unproblematic (AGPL is a superset).
